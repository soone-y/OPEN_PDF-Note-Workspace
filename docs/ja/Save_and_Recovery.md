# 保存と復元

同梱リポジトリ版: (ZIP配布物ではここにバージョンが記載されます)

このソフトでは、元の PDF やノートを守るため、編集途中の作業を自動保護し、原本へ保存する直前には保存前の控えを作ります。内部の保護データは、クラッシュや電源断からの復旧に使います。

## 保存の流れ

このソフトは、編集内容をすぐに原本へ書き込むのではなく、次の順で扱います。

1. 編集内容を内部で自動保護する
2. ファイル・回次・授業を切り替えるときは、保護済みの状態を引き継いで表示を切り替える
3. `Ctrl+S`／「作業保存」、通常終了、または出力の直前に原本を上書きする前の控えを作る
4. 安全な書込みと検証を完了してから原本へ保存する

このため、編集途中のノートや PDF 注釈を守りつつ、原本の途中書込みを避けます。

`Ctrl+S` はノートと注釈データを原本へ保存する操作です。バックアップ作成と安全な書込みを経て更新し、PDF本体は変更しません。自動作業保護だけの状態とは区別してください。

## 開いている原本の保護

表示中のPDF・画像・ノートは、保存済みでも、エクスプローラーなどから削除・移動・名前変更できないように保護します。外部エディタが原本を置き換えて保存する操作も制限されます。

PDFの注釈やノートに内部作業保護（stage）が残っている間は、アプリの動作中、表示を閉じたり別のファイルへ切り替えたりしても元のPDF・ノートの保護を維持します。前回から残るstageも読み込んだ時点で対象のPDF・ノートを保護します。外部で整理するときは、先に「作業保存」で注釈やノートを統合保存し、対象の表示を閉じてください。保護中の編集を明示的に破棄した場合も、そのファイルのstageがすべてなくなり、表示を閉じていれば保護を解除します。表示を閉じるだけでは統合保存しません。アプリの終了後はこの削除防止の保護も終了します。

終了時の統合保存に失敗した場合は、元のファイルを変更せずに通知し、「保留」「復旧」「終了」から選べます。「保留」はアプリを終了せずに作業を続けます。「復旧」は保存できなかった変更の復旧画面を開きます。「終了」は未統合の変更をstageに保持したまま終了し、次回起動時にもう一度統合や復旧を選べます。stageへの保存にも失敗した場合は終了しません。

ほかの理由でも終了できなくならないようにしています。設定や出力などの画面が開いていて終了できないときは、その画面を前面に出して案内します。ワークスペースメモを保存できないときは、「保留」または「コピーして終了」（メモの内容をクリップボードへコピーしてから終了）を選べます。統合保存が30秒以上続くときは、「待つ」または「終了を取りやめる」を選べます。書き込み中に強制的に終了することはありません。次回起動時に開くファイルの記録を保存できなかった場合も終了は続け、次回は前回のファイルを自動では開かないことがあります。

保護中のPDFへの外部操作要求を検知すると、画面の右下付近に短い案内を表示します。原本へ未反映の編集がある場合は「作業保存」を案内し、表示中だけの場合は表示を閉じるよう案内します。通知は音を鳴らさず、フォーカスやクリック操作を奪わずに消えます。連続する要求は原則30秒間まとめ、通知より通常の警告を優先します。操作の種類や利用者の意図は断定しません。通知を取得できない環境でも、原本の削除防止は維持します。

このソフト自身の置換保存・移動では、操作対象の保護だけを短時間解放して再取得します。その間の外部操作まで完全に防ぐものではありません。再取得に失敗した場合は「原本保護: 再取得中」と表示し、ファイルを開き直さなくても自動で再取得を続けます。表示が消えるまでは外部アプリで原本を削除・移動しないでください。

移動が完了していれば、保護の成否とは別に移動先へ参照を更新します。保存の置換後に保護を再取得できなかった場合は、置換済みであることを示したうえで保存の未完了を通知し、内部作業保護と復旧用データを保持します。

「ファイル > PDF・ノートを閉じる」はPDFとノートを両方閉じます。「表示 > 閉じる > PDF／ノート」は片方だけを閉じます。どちらも編集内容を内部で保護してから表示を閉じ、授業・回次の選択は維持します。保護に失敗したときは表示を閉じません。

ノートを閉じるとエディタのundo/redo履歴は終了します。未保存の編集内容は内部の保護データに残り、開き直すと復元されます。

## 使い分け

- 編集を続ける: 通常どおり編集します。自動作業保護が途中状態を保持します。
- 区切りよく確定する: `Ctrl+S` または「保存 > 作業保存」を使います。
- 保存できなかった作業を確認する: 「保存 > 保存状態を確認...」を開きます。
- PDF位置または最終オープン時刻を戻す: 「設定 > 復元」から対象を選びます。バックアップは「保存 > 保存済みファイルのバックアップ」の一覧から復元または個別に削除できます。対象を選んで「詳細...」を押すと、復元先とバックアップ情報の完全なパスを確認・コピーできます。

## 設定などの保存を再試行する

一時パスの登録、テーマ、パレットの保存に失敗した内容は、「保存 > 保存できなかった内容…」で確認できます。一時パス追加前の読み書き確認で拒否された要求も保持します。保存先の権限やセキュリティ制御を確認した後、「再試行」を押すと、アクセスを確認し直して登録・保存します。アクセス確認に失敗した段階では、登録済みの一覧と設定ファイルを変更しません。

この画面では失敗理由と保存予定の内容を確認し、内容や対象パスをコピーできます。対象や設定が途中で変わった場合は、古い要求での上書きを止めます。再試行用のコピーは同じ起動中だけメモリに保持し、終了時に残っている場合は確認を表示します。

失敗時の通知にも「保存 > 保存できなかった内容…」への案内を表示します。一時パスの追加は「ファイル > 一時パス > 再試行」からも実行できます。再試行できる要求が1件なら直接再試行し、複数件なら画面で対象を選びます。

一時パスの追加・再試行では、フォルダーのアクセス確認をバックグラウンドで順番に行います。処理中も現在のPDF・ノート・注釈欄を操作できます。同時に追加できる要求は1件です。確認が完了し、開始時の登録内容と設定が一致した場合に、まとめて登録します。途中でワークスペースや登録内容を変更した場合は、古い結果の反映を止めます。処理中に終了すると、追加を中止してから通常の終了処理へ進みます。

## 保存前に確認すると安心なこと

- ワークスペースのあるドライブに十分な空き容量があること
- 保存先のファイルを、他のソフトで開いたままにしていないこと
- 保存状態に、意図しない保護中の作業が残っていないこと

大きな編集の前や、外部へ渡す前には、`Ctrl+S` で一度統合してからワークスペースを丸ごとコピーしておくと、元に戻す判断がしやすくなります。

## 復元前の注意

保存できなかった保護中のノートや注釈がある状態で原本だけを復元すると、状態が異なることがあります。復元前に「保存状態を確認」で内容を確認するか、意図に応じて先に `Ctrl+S` で保存してください。

復元する理由が「直前の編集を取り消したい」だけなのか、「PDF位置または最終オープン時刻を戻したい」のかを分けて考えてください。前者は編集画面の undo/redo、後者は「設定 > 復元」を使います。保存・終了後の復元に備え、必要なバックアップを残してください。

## 主な保存先

::: details 内部の保護データと保存先を確認する

管理フォルダー名は `__pdf_note_workspace__` です。旧名称フォルダーの自動改名・移行・互換読み込みは行いません。0.9.620 より前の版が `__pdf_note_workspace__` 内で使っていた `__tmp__/__stage__/`（未統合の編集）や `__escape__/`（バックアップ・復旧候補など）も、新しい版は読み込まず、移動も削除もしません。旧版の未統合の編集は、旧版で開いて保存するか、[エクスプローラーで手動で復旧する](#エクスプローラーで手動で復旧する)手順で `__unsaved__` の代わりに `__tmp__/__stage__/` を確かめます。`__tmp__` を削除すると旧版の未統合の編集も消えるため、中身を確かめるまで削除しないでください。

- 内部作業保護: `__pdf_note_workspace__/__unsaved__/`（通常は操作不要）
- バックアップ: `__pdf_note_workspace__/__backup__/`
- 編集内容の復旧: `__pdf_note_workspace__/__recovery__/`
- 書き込めなかった内容・壊れて読めないファイルの退避: `__pdf_note_workspace__/__failed__/`

各フォルダーを削除してよいかと、削除したときの挙動は[管理フォルダー](Help_Reference.md#管理フォルダー__pdf_note_workspace__)と `__pdf_note_workspace__/DELETE_OR_KEEP.txt` にあります。

これらのフォルダを、問題の確認前に削除しないでください。

:::

## 保存に失敗したとき

保護した編集内容を原本へ反映できなかった場合は、本体とは別の復旧ツールで残す内容を確認します。「復旧」を選ぶと、本体は未統合の変更をstageに残したまま終了し、復旧ツールが開きます。「保存 > 保存状態を確認...」で対象を選び、「復旧する」からも開けます。

復旧ツールは、本体が起動できない場合でも、アプリのフォルダーで `pdf_note_workspace.exe --recovery` を実行して直接開けます（ワークスペースを選びます）。ワークスペースのstageをすべて一覧にし、元のファイルが見つからないものも表示します。復旧ツールの動作中は本体を起動できず、本体の動作中は復旧ツールが本体の終了を求めます。競合と読み取り不良は同じ画面で扱い、読み取れない部分がある場合は、確認できた一部を保存することへの確認を求めます。

PDFは、失敗したファイルの注釈グループを元グループへドラッグして追加します。既存の注釈を残し、中央のPDFで完成形を確認します。種類・ページの一覧で数式や図形なども確認でき、注釈の個別編集は行いません。適用先が違う場合はPDFを選び直し、注釈を重ねた状態を確認してから保存します。ノートは参照用の文章を見ながら完成形の本文を編集します。

復旧画面は「保存して終了」または「保留して終了」で復旧ツールの一覧へ戻ります。×を押した場合も、保存・保留・続行を選びます。保留では原本を更新せず、候補を保護して次回へ引き継ぎます。保存や保護に失敗した場合は画面を閉じません。保存先がなくなった場合などは「別ファイルへ保存して終了」で、新しい名前へ救出できます。既存ファイルへの上書きは行いません。

復旧候補と元の失敗データは `__pdf_note_workspace__/__recovery__/` に保持します。問題の確認前に削除しないでください。PDFと注釈を別名保存する途中で失敗した場合も、候補と作成済みのファイルを残します。再試行は別の新しい名前で行ってください。

エラーが出た場合は、アプリをすぐに何度も再起動したり、内部作業保護やバックアップを削除したりしないでください。エラー表示、対象ファイル名、操作時刻を控え、[Troubleshooting.md](Troubleshooting.md) の手順に従ってください。

## エクスプローラーで手動で復旧する

アプリを使わずに、エクスプローラーとテキストエディタで未統合の編集（stage）を取り出す手順です。アプリが起動できる場合は、先に復旧ツール（アプリの「復旧」、または `pdf_note_workspace.exe --recovery`）を使ってください。

始める前に:
1. アプリと復旧ツールをすべて終了します。
2. ワークスペース全体を別の場所へコピーして控えを作ります。控えには触れません。
3. 元のファイル（ノート・PDF・.clrop）を置き換える前に、そのファイルのコピーを作ります。

場所（ワークスペース直下の `__pdf_note_workspace__\__unsaved__\`）:
- `note\` ノートの未統合の内容。`note_<識別子>_r<番号>.stage` が本文で、元のノートと同じ文字コード・改行のままです。同名に `.meta.txt` を付けたファイルの `target=` が元のノート、`rev=` が版番号です。
- `clrop\` PDF注釈の未統合の内容。`clrop_<識別子>_r<番号>.clrop.stage` が .clrop と同じ形式の注釈データです。`.meta.txt` の `target=` が元のPDF、`dest=` が書き込み先の .clrop です。
- `clrop_journal\` 最後のstage以降に追加した注釈の記録です。手動では統合できません。
- `note_journal\` 最後のstage以降のノートの編集の記録（`notej_*.bin`・`notee_*.bin`）です。手動では統合できません。
- 保存前のバックアップは `__pdf_note_workspace__\__backup__\`、復旧ツールの候補は `__pdf_note_workspace__\__recovery__\` にあります。

ノートを戻す:
1. `note\` の `.meta.txt` をメモ帳で開き、`target=` で対象を確かめます。同じ対象が複数ある場合は `rev=` が最も大きいものが最新です。
2. 対応する `.stage` をメモ帳などで開いて内容を確かめます。
3. `.stage` をコピーし、`target=` のファイル名（拡張子を含む）に変えて、元のノートの場所へ置きます。元のノートが残っている場合は、先にそのコピーを作ってから置き換えます。
4. `note_journal\` にファイルがある場合、`.stage` には最後のstage以降の編集が入っていないことがあります。その分は手動では戻せません。アプリまたは復旧ツールで統合してください。

PDF注釈を戻す:
1. `clrop\` の `.meta.txt` で `target=`（PDF）と `dest=`（.clrop）を確かめます。`rev=` が最も大きいものが最新です。
2. `dest=` の .clrop が残っている場合は、先にそのコピーを作ります。
3. `.clrop.stage` をコピーし、`dest=` のファイル名（PDFと同じ名前で拡張子が .clrop）に変えて、PDFと同じフォルダーへ置きます。
4. `clrop_journal\` に同じ識別子のファイルがある場合、その分の注釈は手動では戻せません。アプリまたは復旧ツールで統合してください。

後片付け:
戻した内容をアプリで開いて確かめるまで、`__unsaved__` の中身は消さないでください。確かめた後は、アプリの「保存 > 保存状態を確認...」から破棄します。
